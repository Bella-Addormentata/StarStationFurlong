# External Infrastructure Register

> **Purpose:** the one date-stamped list of every outside host, service or network a shipped Star Station Furlong build can contact — by name, or as a class for the http(s) links a room record can carry — with the class each falls in: being removed, exempt, optional, or local. **The principle it serves (Dorkmo, 2026‑10‑12):** the station relies on no central infrastructure such as websites. Rulings it inherits: the serverless-sources ruling of 2026‑10‑04 (the convenience lanes are off by default, [sovereignty.ts](../../prototypes/0.29.0-core-loop-demo/src/sovereignty.ts)) and [#231 D1](https://github.com/Bella-Addormentata/StarStationFurlong/issues/231) of 2026‑10‑11 (peer-protocol chain access, [sovereign plan §14](../../brainstorming/sovereign-treasury-serverless-plan.md)).
>
> **Owner:** whoever touches a row's code. **Rule:** a change that makes a build contact a new host, or changes a row's default, updates this file in the same PR and names the row in the PR description; a row that owes work points at its TODO item. **Re-verify** every row with the commands in §6 before each release and stamp the Checked column.

## 1. The classes

- **Being removed** — a dependency that breaks the principle. The row stays until no shipped code names the host, then moves to §7.
- **Exempt** — central infrastructure the project accepts, each with the condition that makes it acceptable (bootstrap only, build machine only, distribution only) and the sovereign upgrade that would retire it.
- **Optional** — off by default. The row says who turns it on (a build flag, an operator's environment variable, a room owner, a viewer's consent) and what the player sees. A peer's record can never turn a lane on; where a lane, once on, also follows hosts a peer names, the row says so (operator relays).
- **Local** — not central at all (the LAN, the player's own router, loopback). Listed so nobody mistakes them for third parties.

Paths below are relative to the repository root; line numbers are those of main `97c10988` on 2026‑10‑12.

## 6. How to re-verify

Run from the repository root; every hit must have a row above.

```sh
# every URL or hostname in the node
grep -n -o -E 'https?://[^" )]+|[a-z0-9-]+[.](org|com|net|io|link|computer)' prototypes/0.29.0-core-loop-demo/ssf-p2p-node/src/*.rs
# the gateway call sites (must be empty once §2's first row has moved to §7)
grep -rn 'CoinsetClient::' prototypes/0.29.0-core-loop-demo/ssf-p2p-node/src
# every literal external URL in the browser
grep -rn -o -E 'https?://[A-Za-z0-9./_-]+' prototypes/0.29.0-core-loop-demo/src --include='*.ts' | grep -v '[.]test[.]ts'
# every dynamic network sink in the browser (fetch and its injectable aliases, WebSocket, EventSource, WebTransport, an assigned src) and every navigation sink (a generated href, an assigned location, window.open), in TypeScript and in the two runtime HTML pages; each hit must resolve to the page's own origin, the viewer's own node, or a room-record URL that passed urlConsent (tvConsent.ts), or it needs a row above. The first line lists the fetch aliases (fetchImpl and fetchFn today); a new one goes into the second line's pattern
grep -rn 'typeof fetch' prototypes/0.29.0-core-loop-demo/src --include='*.ts' | grep -v '[.]test[.]ts'
grep -rn -E '(^|[^A-Za-z])(fetch|fetchImpl|fetchFn)\(|new WebSocket\(|new EventSource\(|new WebTransport\(|\.src\s*=|href=|\.href\s*=|window\.open\(' prototypes/0.29.0-core-loop-demo/src --include='*.ts' | grep -v '[.]test[.]ts' | grep -v -E 'startPrefetch|stopPrefetch'
grep -n -E 'https?://|fetch\(|\.src\s*=|<script[^>]*src=|href=|window\.open\(' prototypes/0.29.0-core-loop-demo/index.html prototypes/0.29.0-core-loop-demo/public/arcade/frame.html
# the desktop shell: no updater endpoint, no remote URLs
grep -n -i 'updater\|endpoints\|https\?://' prototypes/0.29.0-core-loop-demo/src-tauri/tauri.conf.json
# the Mainline DHT bootstrap list lives in the n0-mainline crate, not in the node (main.rs passes no override): expect the four hosts of §3's first row
grep -n -A5 'DEFAULT_BOOTSTRAP_NODES' ~/.cargo/registry/src/*/n0-mainline-*/src/actor/config.rs
# what iroh does when the node configures nothing (expect RelayMode::Disabled, no address lookup)
grep -n -B1 -A3 'pub fn empty()' ~/.cargo/registry/src/*/iroh-1.*/src/endpoint.rs
```

On main `97c10988` the TypeScript line finds seventeen hits and the HTML line three, every one accounted for: the page's own origin (the photo standees in `furniture.ts`, the party tracks in `partyAudio.ts`, the built-in ROMs under `/arcade/roms/` in `arcadeNesSession.ts`, the emulator frame and the emulator-files probe in `arcadeEmulator.ts`, the probe fetching `loader.js` from the page's own origin only since a cross-origin data path returns `unknown` unfetched, the replay spike's ROM in `arcadeReplaySpike.ts`, whose page `replay-spike.html` is a dev-server page and not a build input); the viewer's own node, or the remote node a pass names when the browser has none (the bridge row of §4): `/api/fingerprint` and the WebTransport session in `main.ts` and `network/NetworkProvider.ts`; room-record URLs behind `urlConsent` (the TV's video source in `tvTheatre.ts`, the game link in `arcadeStage.ts`, and the TV's redirect probe in `tvConsent.ts`, a CORS HEAD to a host the viewer already consented to); and the convenience lanes (the YouTube API script and the archive.org embed in `tvTheatre.ts`, the archive.org metadata lookup in `tvUI.ts`), none reached before the consent gate let the source through; and the two navigation sinks, the arcade's GitHub source link in `arcadeUI.ts` (the GitHub row of §3) and a reload of the page's own origin in `devMenu.ts`. Of the three HTML hits, `index.html` loads only `/src/index-inline.css` and `/src/main.ts`, and the arcade frame loads the EmulatorJS loader from the data path it is handed: the station's own `/emulatorjs/` by default, `cdn.emulatorjs.org` only on the CDN lane of §4.

A packet capture of a default node at startup and across one 5-minute re-check is the end-to-end check: after §2 is done it shows DHT bootstrap traffic, mDNS, the router, peers, and nothing else.
